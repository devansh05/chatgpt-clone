## Initiative 3 — Authentication With Clerk

**3.1 Install & configure Clerk** — `package.json` (`@clerk/nextjs`), env vars: `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY`, `CLERK_SECRET_KEY`, sign-in/redirect URLs.

**3.2 Edge middleware (`proxy.ts`, not `middleware.ts`)** — `proxy.ts` — `export default clerkMiddleware()` + `matcher` config skipping static assets. *Correction to the original note:* this **isn't a bug**. Per `AGENTS.md`, this is a customized Next.js build where the middleware entrypoint has been renamed — `node_modules/next/dist/lib/constants.js` defines both `MIDDLEWARE_FILENAME = 'middleware'` and `PROXY_FILENAME = 'proxy'`, and `isMiddlewareFile()` in `next/dist/build/utils.js` accepts *either* `middleware.ts` or `proxy.ts` as the edge entrypoint. So `proxy.ts` at the project root is the correct, working filename for this Next.js version — worth calling out as a "breaking change from your training data" gotcha instead.

**3.3 Wrap the app in `ClerkProvider`** — `app/layout.tsx` — add `ClerkProvider` as the outermost provider (around `QueryProvider`).

**3.4 Public auth routes** — `app/(auth)/layout.tsx` (centered card shell: `flex flex-col h-screen items-center justify-center`), `app/(auth)/sign-in/[[...sign-in]]/page.tsx` (`<SignIn forceRedirectUrl="/" />`).

**3.5 Protect the app route group** — `app/(root)/layout.tsx` — `await auth.protect()` before rendering any child route.

**3.6 Sync Clerk → Prisma `User`** — `features/auth/actions/onboard.ts` (`onBoard()` — `currentUser()` + `prisma.user.upsert`), `features/auth/actions/require-user.ts` (`requireUser()` — `auth.protect()` + `prisma.user.findUnique`, throws if onboarding hasn't run yet), `features/auth/index.ts` barrel exporting both. *(Not `lib/onboard.ts` / `lib/auth.ts` — auth is its own feature folder.)*

## Initiative 4 — Conversations and Messages Schema Setup

**4.1 `Conversation` model** — `prisma/schema.prisma` — `title` (default `"New Chat"`), `model`, `systemPrompt`, `isPinned`, `isArchived`, `lastMessageAt` (denormalized for sidebar sort).

**4.2 `Message` model + enums** — `MessageRole` (`USER/ASSISTANT/SYSTEM/TOOL`), `MessageStatus` (`PENDING/COMPLETE/ERROR`); `Message` fields: `content` (plain text), `parts` (`Json?`, full AI SDK `UIMessage.parts`), `metadata`, self-relation `parentId`/`children` (`@relation("MessageBranches")`) for future branching.

**4.3 Relations & indexes** — `User.conversations`, `Conversation.messages`, `onDelete: Cascade`; composite indexes `[userId, lastMessageAt desc]` and `[userId, isPinned, lastMessageAt desc]` on `Conversation`; `[conversationId, createdAt asc]` on `Message`.

**4.4 Migrate** — same migration as 2.4 (`prisma/migrations/20260710070301_init/migration.sql`) — `Conversation`/`Message` were part of the single initial migration, not a separate one; regenerate client.

## Initiative 8 — Chat Streaming and Saving to Database

**8.1 Lock down and resolve the conversation** — `app/api/chat/route.ts` — `auth.protect()`, `requireUser()`, `prisma.conversation.findFirst({ id, userId })`, 404 if missing.

**8.2 Persistence helpers** — `features/ai/actions/chat-store.ts` (**not** `lib/chat/store.ts`) — `loadChatMessages(conversationId)` (DB rows → `UIMessage[]`, falling back to `[{ type: "text", text: content }]` if `parts` is empty), `saveChatMessages(conversationId, messages, { updateTitle })` (upsert per message + bump `lastMessageAt`).

**8.3 Save the user's message before generating a reply** — `route.ts` — compares the incoming `message.id` against `loadChatMessages` results to avoid double-saving, then `saveChatMessages(id, [message])`.

**8.4 Save the assistant's reply as it finishes** — `route.ts` — `result.consumeStream()` (keeps saving even if the client disconnects), `toUIMessageStream({ onEnd: async ({ messages }) => saveChatMessages(id, messages, { updateTitle: false }) })`, `generateMessageId: createIdGenerator({ prefix: "msg", size: 16 })`.

**8.5 Auto-title new chats** — `features/ai/actions/chat-store.ts` `saveChatMessages` — if the conversation's title is still `"New Chat"` and there's a first user message, set the title from it (`slice(0, 48)`).

**8.6 Live-refresh the sidebar** — `features/messages/components/conversation-view.tsx` — `useChat({ onFinish: () => queryClient.invalidateQueries({ queryKey: queryKeys.conversations.all }) })` so the renamed title/reordered list shows immediately.

## Initiative 9 — Loading Chat History and Wrapping Up

**9.1 Load persisted history into the page** — `app/(root)/c/[id]/page.tsx` — `loadChatMessages(id)` (from `@/features/ai/actions/chat-store`) on the server, passed as `initialMessages` prop.

**9.2 Hydrate `useChat` with history** — `features/messages/components/conversation-view.tsx` — `useChat({ id: conversationId, messages: initialMessages, transport })`; `key={id}` on `<ConversationView>` (in `app/(root)/c/[id]/page.tsx`) so switching chats remounts state cleanly.

**9.3 Error handling** — `conversation-view.tsx` — `onError: (error) => toast.error(error.message)`; server-side `try/catch` around `saveChatMessages` inside the `onEnd` callback logs (`console.error`) instead of crashing the stream.

**9.4 Final UI polish** — Confirm theme toggle, `TooltipProvider`, `Toaster` all wired from Initiatives 1/3; metadata (`title: "ChaiGPT"`, `description: "Chat with ChaiGPT"`) and favicon in `app/layout.tsx` / `app/favicon.ico`.

**9.5 Bonus/optional module callout** — `features/messages/actions/message-actions.ts` + `features/messages/hooks/use-messages.ts` implement a manual (non-streaming) send/CRUD flow — useful as an exercise or fallback, but not what the live chat UI (`conversation-view.tsx`) actually uses.

**9.6 Deployment checklist** — Required env vars (`DATABASE_URL`, `OPENAI_API_KEY`, Clerk keys), `prisma migrate deploy` on the target DB, `npm run build && npm run start` (or the Bun equivalents — this repo also ships a `bun.lock`).
